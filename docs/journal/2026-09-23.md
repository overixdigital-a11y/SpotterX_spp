### Sesion 4 · Fix constraint `notifications_type_check` (faltaba 'orden') -> checkout caia (migracion 00035)

## Contexto
El usuario reporto: "cuando quiero simular una compra me sale: new row for relation 'notifications' violates check constraint 'notifications_type_check'". El trigger `notify_market_order` (00026) inserta una notificacion `type='orden'` al crear la orden con `market_checkout`, y la CHECK la rechazaba.

## Decisiones
- Se verifico el estado real de la constraint en la DB (`select pg_get_constraintdef(oid) from pg_constraint where conname='notifications_type_check';`): devolvio la lista de 00015 (`pulse, comment, follow, message, checkin, vencimiento, solicitud_staff, staff_aprobado`) SIN `'orden'`.
- Causa raiz: la constraint se re-crea en CADA migracion (00005, 00011, 00015, 00026) con drop+add, y cada version vieja trae SOLO su lista del momento. En algun momento se re-ejecuto una migracion vieja en el SQL Editor despues de la 00026 y piso el tipo `'orden'`. Las migraciones NO son idempotentes entre si.
- Fix: re-crear la constraint con la LISTA ACUMULATIVA COMPLETA de tipos. Sin cambios de frontend (el trigger ya usaba `'orden'`).

## Implementado
- Migracion nueva `supabase/migrations/00035_notifications_type_orden.sql` (idempotente, `drop constraint if exists`) con la lista completa: `('pulse','comment','follow','message','checkin','vencimiento','solicitud_staff','staff_aprobado','orden')`.
- SQL pasado al usuario para correr en SQL Editor (2 lineas ALTER).
- AGENTS.md: bloque Lote 24 con la leccion (constraint no idempotente; no re-correr migraciones viejas de notifications).

### Sesion 5 · Rebrand SpotterShop + monetizacion por publicaciones (commit f4b859b + migracion 00036)

## Contexto
Con el checkout funcionando (Sesion 4), el usuario decidio repensar la monetizacion del marketplace: eliminar la comision por venta y cobrar **por publicacion** (estilo clasificados). Tambien pidio rebrandear la tienda como **SpotterShop** (solo etiquetas; las rutas `/market/*` no cambian).

## Decisiones
- **Sin comision por venta**: el vendedor cobra el 100% de cada venta. Quedan sin uso `commissionFor`/`admin_set_commission` (no se borran; las ordenes viejas conservan su snapshot `platform_fee`, las nuevas 0).
- **Se cobra por publicacion** (una sola vez por publicacion creada): cupo gratis **global configurable** (default 3, key `free_publishes`) + **precio por publicacion configurable** (default $100, key `publish_price`) en `platform_config`. Editable desde `/market/admin`.
- **Override individual**: `profiles.shop_free_limit int` (NULL = usa el global). El admin lo ajusta por publicador (0 = paga todo). Ranking de publicadores en el admin para otorgar premios (publicaciones gratis) a los top.
- **Sin saldo - no publica**: la RPC `market_publish` valida cupo/saldo y falla con "Saldo insuficiente"; `/market/crear` muestra banner con link a la billetera.
- Solo `active` + `paused` cuentan para el cupo (vender/borrar libera cupo).
- El KPI de ingresos usa una RPC `security definer` (`admin_publish_revenue`) porque el admin NO lee `wallet_transactions` ajenas por RLS.
- La billetera registra cada publicacion paga como `wallet_transactions type='publish'` (CK ampliada con lista acumulativa completa).

## Implementado
- Migracion `supabase/migrations/00036_spotter_shop.sql` (PENDIENTE de correr): columnas `profiles.shop_free_limit` y `wallets.pub_count`; seeds `free_publishes`/`publish_price`; CHECK `wallet_transactions` re-creada con `'publish'`; RPCs `market_publish`, `get_publish_quote`, `admin_set_publication_config`, `admin_set_user_free_limit`, `admin_publish_revenue`. `market_checkout`/`buy_from_wallet` ya vienen SIN comision (fee 0, vendedor cobra el 100%).
- Rebrand SpotterShop en labels: `/market` h1, card `/perfil`, pill `MarketShell`, nav `AdminShell` (plataforma) y `TrainingShell`, notif `orden`, "Volver a SpotterShop".
- `/market/crear`: banner de cupo via `get_publish_quote` (restantes / costo / saldo) + publica con `market_publish` + toast/link a billetera si no hay saldo.
- `/market/carrito`: sin fila ni calculo de comision.
- `/market/admin`: seccion **Monetizacion SpotterShop** (global gratis + precio) + card **Publicadores - ranking y premios** (ordenados por vigentes, stepper -/+, Aplicar, "Global" para volver al cupo global) + KPI "Ingresos pub".
- `/admin/market`: KPI "Ingresos por publicaciones" (era "Comision total").
- Lint 0 errores + build OK (44 rutas). Commit `f4b859b` pusheado (deploy automatico).
