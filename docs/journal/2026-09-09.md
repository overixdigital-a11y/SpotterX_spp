## Rutinas con series por ejercicio + registro del alumno por checks

## Contexto
- El profe creaba ejercicios con campos planos (series/reps/peso/descanso como texto suelto), imposible hacer un programa realista con pesos progresivos por serie.
- El alumno tenía que cargar valores manualmente por campo (frustrante y propenso a error).
- El upsert del alumno (`onConflict: "item_id,log_date"`) fallaría: `trainer_routine_logs` no tenía constraint único.

## Decisiones
- **Modelo de series**: `data.series = [{ reps, weight_kg, rest_seconds }, ...]` por ejercicio en `trainer_routine_items`. Solo en disciplinas de fuerza: **musculación, crossfit, calistenia, funcional** (`isSeriesDiscipline()`). El resto queda con campos planos (cardio, running, yoga, HIIT, etc.).
- **El profe construye las series**: fila por serie con reps/peso/descanso, botón "+ Serie" agrega fila, cada fila con ✕. Rutinas legacy planas se convierten a series al editar/guardar.
- **El alumno solo marca**: check ✓ por serie + campo de **peso real** editable (única modificación, para superar el plan). reps/descanso fijos. Log: 1 por (ejercicio, día) con `data.series = [{ done, weight_kg }]`.
- **Migración 00017**: constraint único `(item_id, log_date)` para que el upsert funcione.

## Implementado
- **`00017_routine_logs_unique.sql`** (NUEVO, pendiente de correr): `ALTER TABLE trainer_routine_logs ADD CONSTRAINT trainer_routine_logs_item_date_unique UNIQUE (item_id, log_date)`.
- **`src/lib/disciplines.ts`**: `Series`, `SeriesLog`, `isSeriesDiscipline`, `getSeries`, `resolveSeries`, `legacyToSeries`, `formatSeries`.
- **`entrenamiento/alumno/[id]/page.tsx`**: editor de series por ejercicio (+ Serie / ✕), rendering de series en la lista de rutinas, normalización legacy→series al guardar (`resolveSeries`).
- **`mi-entrenamiento/page.tsx`**: por serie → check ✓ + input peso real (step 0.5, precargado del plan). `saveLogs` → upsert por item/día. `loadProgress` usa el mayor peso real de las series hechas. Disciplinas planas conservan el logging anterior.

## Catálogo de ejercicios con buscador (solo rutinas)

## Contexto
- El profe escribía cada nombre de ejercicio a mano en el form de rutinas (con el nuevo editor de series), lento y propenso a errores/duplicados.

## Decisiones
- **Catálogo global compartido**: una tabla `exercises` que todos los profes leen y pueden ampliar (insert con `created_by`). Seed inicial con ~145 ejercicios por disciplina.
- **Solo en rutinas**: los planes NO se tocan (quedan para alimentación cuando terminemos las rutinas).
- **Sugeridos primero**: el dropdown agrupa por disciplina (si la rutina es de musculación, muestra musculación primero y el resto debajo) y filtra por texto.
- **"+ Crear 'texto'"**: si el nombre no existe en la biblioteca, se agrega al catálogo (dedupe por `lower(name)`) y se selecciona.

## Implementado
- **`00018_exercises_catalog.sql`** (NUEVO, pendiente de correr): tabla `exercises` (name, discipline, created_by, created_at) + RLS (select todos / insert autenticados) + unique `lower(name)` + realtime + seed de ~145 ejercicios.
