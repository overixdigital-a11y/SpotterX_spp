# 2026-09-09

## Contexto
- Continuación de Fase A del plan `PLAN_PULIDO.md`. El alumno no veía planes/rutinas del profe aunque existían en la DB.
- Diagnóstico: `trainer_students` nunca se creaba al agregar alumnos/profes al gym, por lo que las queries del profe y del alumno devolvían 0 resultados.
- UI de planes vs rutinas era ambigua: ambos tabs se veían similares, sin distinguir entrenamiento de alimentación.

## Decisiones
- **trainer_students auto-creado**: en vez de pedir al usuario crear la vinculación manual, se auto-inserta `trainer_students` en los 4 puntos de entrada: `confirmAlumno`, `addProfesor`, `approveRequest` (frontend) y `invite-member` (edge function).
- **Planes vs Rutinas explícitos**: sin migración nueva. Se usa el campo `content` existente de `trainer_plans` para guía nutricional cuando `kind='alimentacion'`. Se distingue visualmente con chips de color (naranja=alimentación, neón=entrenamiento) y labels específicos ("Comidas del día" vs "Día N").
- **Rutinas con plan**: se agregó `plan_id` a la interfaz `Routine` (ya existía en la tabla) para mostrar chip "Del plan: [título]" en cada rutina.

## Implementado
- **`gimnasio/miembros/page.tsx`**: `confirmAlumno` (L320-368) busca `gym_staff` activos y crea `trainer_students` para cada profe; `addProfesor` (L370-399) busca `gym_memberships` activos y crea `trainer_students` para cada alumno.
- **`gimnasio/page.tsx`**: `approveRequest` (aprobar solicitud de profe) crea `trainer_students` para todos los alumnos activos del gym.
- **`invite-member/index.ts`**: edge function ahora crea `trainer_students` al agregar profesor (vincula con alumnos activos) o alumno (vincula con profes activos).
- **`mi-entrenamiento/page.tsx`**: tab Planes muestra chip naranja "Alimentación" + guía nutricional con borde naranja para `kind='alimentacion'`; chip neón "Entrenamiento" para `kind='entrenamiento'`. Rutinas muestran chip "Del plan: [título]" cuando tienen `plan_id`. Eliminado `KIND_LABEL` no usado.
- **`entrenamiento/alumno/[id]/page.tsx`**: textarea de contenido del plan muestra placeholder de guía nutricional cuando `kind='alimentacion'` (4 rows vs 2).
